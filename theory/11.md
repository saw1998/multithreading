4.3 Recursive Mutex — When and Why

```cpp
#include <mutex>
#include <iostream>

// ===================================================================
// RECURSIVE MUTEX
// ===================================================================
/*
 * PROBLEM IT SOLVES:
 * What if a function that holds a mutex CALLS ANOTHER function
 * that tries to acquire the SAME mutex?
 * 
 * With regular mutex: DEADLOCK (thread tries to lock mutex it already owns)
 * With recursive_mutex: OK — same thread can lock multiple times
 * 
 * INTERNALLY:
 * recursive_mutex stores:
 *   - Thread ID of current owner
 *   - Lock count (how many times current owner locked it)
 * 
 * lock(): if current thread is owner → increment count
 *         if no owner → set owner to current thread, count=1
 *         if other thread is owner → block
 * 
 * unlock(): decrement count
 *           if count reaches 0 → release, wake waiters
 * 
 * PROBLEM WITH recursive_mutex:
 * It's almost always a sign of BAD DESIGN.
 * Better: separate "public" functions (which lock) from
 *         "internal" functions (which assume lock is already held)
 */

class FileProcessor {
    std::recursive_mutex mtx;
    std::vector<std::string> files;
    
public:
    // This locks the mutex
    void processFile(const std::string& file) {
        std::lock_guard<std::recursive_mutex> lock(mtx);
        std::cout << "Processing: " << file << "\n";
        files.push_back(file);
        
        // What if we need to also log?
        logOperation("Processed: " + file); // This also locks!
    }
    
    // This ALSO locks the mutex (same one!)
    void logOperation(const std::string& msg) {
        std::lock_guard<std::recursive_mutex> lock(mtx);
        // With regular mutex: DEADLOCK here!
        // With recursive_mutex: OK (lock count goes to 2)
        std::cout << "[LOG] " << msg << "\n";
    }
};

// ===== BETTER DESIGN =====
class BetterFileProcessor {
    std::mutex mtx;
    std::vector<std::string> files;
    
    // Private: does NOT lock (assumes caller holds lock)
    void logImpl(const std::string& msg) {
        std::cout << "[LOG] " << msg << "\n";
    }
    
public:
    // Public: locks, then calls private impl
    void processFile(const std::string& file) {
        std::lock_guard<std::mutex> lock(mtx);
        std::cout << "Processing: " << file << "\n";
        files.push_back(file);
        logImpl("Processed: " + file); // no double-lock!
    }
    
    void logOperation(const std::string& msg) {
        std::lock_guard<std::mutex> lock(mtx);
        logImpl(msg);
    }
};
```
