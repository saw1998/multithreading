│           CONCURRENCY DECISION TREE                                 │
│                                                                     │
│  Is data accessed by multiple threads?                              │
│  NO → No synchronization needed                                     │
│  YES ↓                                                              │
│                                                                     │
│  Is there any WRITE access?                                         │
│  NO → shared_mutex + shared_lock (readers concurrent)              │
│  YES ↓                                                              │
│                                                                     │
│  Is it a simple counter/flag?                                       │
│  YES → atomic<T>                                                    │
│  NO ↓                                                               │
│                                                                     │
│  Do threads need to WAIT for a condition?                           │
│  NO → mutex + lock_guard                                            │
│  YES ↓                                                              │
│                                                                     │
│  What condition?                                                    │
│  Queue has items → condition_variable (producer-consumer)           │
│  N things completed → latch (one-shot)                              │
│  All threads reached point → barrier (repeated)                     │
│  N permits available → semaphore                                    │
│  Other thread's value → promise/future                              │
│                                                                     │
│  Multiple mutexes needed?                                           │
│  YES → scoped_lock (deadlock-free)                                  │
│                                                                     │
│  Need extreme performance on hot path?                              │
│  YES → Consider lock-free with atomic + CAS                         │
│        (measure first! premature optimization is evil)              │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│           THE 10 COMMANDMENTS OF CONCURRENT PROGRAMMING             │
│                                                                     │
│  1. PROTECT ALL SHARED MUTABLE STATE                                │
│     If two threads can both see it AND one modifies it: LOCK IT    │
│                                                                     │
│  2. HOLD LOCKS AS BRIEFLY AS POSSIBLE                               │
│     Lock → critical section → unlock. Nothing else under lock.     │
│                                                                     │
│  3. NEVER CALL FOREIGN CODE WHILE HOLDING A LOCK                   │
│     Callbacks, virtual functions, lambdas — they might lock too!   │
│                                                                     │
│  4. ALWAYS USE RAII FOR LOCKS                                       │
│     lock_guard, unique_lock
