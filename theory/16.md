PART 7: ATOMICS — LOCK-FREE PROGRAMMING
7.1 The Problem with Locks

LOCKS ARE EXPENSIVE:
1. Thread suspension and waking = OS involvement = microseconds
2. Cache coherency traffic
3. No progress guarantee if a thread dies while holding lock
4. Can't be used in signal handlers

FOR HOT PATHS (millions of operations per second),
we need something faster: ATOMIC OPERATIONS

WHAT IS AN ATOMIC OPERATION?
An operation that cannot be interrupted — it completes
as one indivisible unit from the perspective of other threads.

HOW DOES HARDWARE SUPPORT THIS?
Modern CPUs have special instructions:
- x86: LOCK CMPXCHG (compare-exchange), LOCK ADD, etc.
- ARM: LDREX/STREX, LDADD, etc.

These instructions use the CPU's memory bus:
1. "Lock" the memory bus (no other CPU can access this memory)
2. Perform the operation
3. "Unlock" the bus
All in ONE atomic step!
