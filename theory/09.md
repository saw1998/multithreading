PART 4: MUTEX — MUTUAL EXCLUSION
4.1 What is a Mutex? Deep Dive


REAL WORLD ANALOGY: The Bathroom Key

Imagine an office with ONE bathroom.
Only ONE person can use it at a time.
They have ONE key hanging on a hook.

Person wants to use bathroom:
1. Check if key is on hook
2. If YES: take key, use bathroom, return key
3. If NO: wait until key appears, then take it

MUTEX works EXACTLY the same way:
- The "key" = the mutex
- "Taking the key" = locking the mutex
- "Returning the key" = unlocking the mutex
- "Using the bathroom" = critical section (protected code)

┌──────────────────────────────────────────────────────────────┐
│                  MUTEX INTERNALS                             │
│                                                              │
│  Mutex has ONE bit: 0 = unlocked, 1 = locked                │
│                                                              │
│  lock():                                                     │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  while (true) {                                     │    │
│  │    // THIS IS ONE ATOMIC OPERATION (hardware level) │    │
│  │    if (mutex_bit == 0) {                            │    │
│  │        mutex_bit = 1;  // CAS instruction           │    │
│  │        return;  // got the lock!                    │    │
│  │    }                                                │    │
│  │    // mutex is locked: suspend this thread          │    │
│  │    OS.suspendThisThread();                          │    │
│  │    // OS puts us in a "wait queue" for this mutex   │    │
│  │  }                                                  │    │
│  └─────────────────────────────────────────────────────┘    │
│                                                              │
│  unlock():                                                   │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  mutex_bit = 0;  // release                         │    │
│  │  // Wake up ONE waiting thread (if any)             │    │
│  │  OS.wakeOneWaiter(this_mutex);                      │    │
│  └─────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────┘

The KEY PROPERTY of mutex lock/unlock:
These operations use special CPU instructions (CMPXCHG, etc.)
that are ATOMIC — they cannot be interrupted halfway through.
This is what makes them safe for multi-threading!
