PART 3: DATA RACES — THE ROOT OF ALL CONCURRENCY EVIL
3.1 What is a Data Race? Deep Dive


THE FUNDAMENTAL PROBLEM:

RAM stores: counter = 0

Thread 1 wants to do: counter++
Thread 2 wants to do: counter++
Expected result: counter = 2

BUT "counter++" is NOT ONE instruction!
It's THREE instructions in assembly:

THREAD 1                    THREAD 2
---------                   ---------
LOAD R1, [counter]   (R1=0)
                            LOAD R2, [counter]  (R2=0)
ADD R1, 1            (R1=1)
                            ADD R2, 1           (R2=1)
STORE [counter], R1  (counter=1)
                            STORE [counter], R2 (counter=1!!)

RESULT: counter = 1 instead of 2!
One increment is LOST!

This is called a DATA RACE:
- Two threads access the same memory
- At least one is a WRITE
- No synchronization between them
- UNDEFINED BEHAVIOR in C++!

"Undefined Behavior" means: anything can happen
- Wrong results (most common)
- Crash
- Data corruption
- The program appears to work fine sometimes
  (the most dangerous kind!)
